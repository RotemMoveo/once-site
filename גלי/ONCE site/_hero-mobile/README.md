סרגל הסינון. בדסקטופ זו נשימה מכוונת ברוחב 1440; ב-375 זהו הקיפול הראשון כולו.

## מה יש כאן

`build.py` מייצר 14 עותקים — `projects-v0..v6` ו-`news-v0..v6` — של העמודים
האמיתיים, עם טלאי מוזרק לפני `</body>`: גיליון `@media (max-width:768px)`
ולפעמים כמה שורות JS. הדסקטופ אינו נוגע, וכללי ה-1439 של כל עמוד ממשיכים
לשלוט מעל 768.

## כשנבחר וריאנט

* v1 / v2 — הכללים גנריים ברובם. מה שנוגע ל-`.bcr-wrap` ולקצב הראש שייך
  ל-`css/chrome.css` ליד הבלוק הקיים של `@media (max-width:768px)` (שכבר
  מכווץ שם את `.nav-gap` ל-64 ואת `.bcr-wrap` ל-40); מזהי הצמתים (`#n3`,
  `#n328`…) הם פר-עמוד ונשארים בגיליון של העמוד.
* v3 / v4 — התמונות כאן הן **placeholder**: `3465d5c6c01d7b36.jpg`
  לפרויקטים, `28323d6fc880a2ba.jpg` לחדשות. הבחירה האמיתית היא החלטה
  תוכנית — האם זו תמונה קבועה לעמוד, או התמונה של הפריט הראשון.
* v4 מוריד את `.nav-gap` ומחזיר את התפריט להתנהגות השקופה-עד-גלילה. העמודים
  האלה מכריזים `<body data-nav="light">`, ולכן צריך או להסיר את התכונה
  במובייל או להשאיר את הקוד שכאן, שמנטרל אותה מתחת ל-768.
* **מעל 768 ועד 1439** הטלאי אינו חל, והראש נשאר כפי שהוא היום. אם נרצה
  שגם טאבלט ייהנה מהתיקון, יש להעלות את הסף — אבל ‎v3/v4/v5 מניחים רוחב של
  טלפון, אז כנראה נכון להשאיר את סף התמונה ב-768 ולתת ל-v1/v2 סף רחב יותר.
* אחרי בחירה: להחיל גם על `article.html` ו-`search.html` (אותה בעיה בדיוק),
  להעלות את מספר ה-`?v=` של `css/chrome.css`, ולהריץ `python3 _en-build/build.py`.

התיקייה הזו היא חומר עבודה בלבד ואינה חלק מהאתר — אפשר למחוק אותה אחרי
ההחלטה, בדיוק כמו `_footer-options/`.
